Requisito PC3 · Arquitectura 03 / 13

Topología Distribuida del Sistema

Dos servicios desacoplados para aislar fallas del procesamiento de imágenes.

🌐 1. API Principal (NestJS + TypeScript)
  • Atiende peticiones HTTP REST de usuarios en tiempo real.
  • Maneja autenticación, sesiones seguras y cálculo de reparto.
  • Responde de inmediato con estado PROCESANDO al subir comprobantes sin bloquear al usuario.
⚙️ 2. Worker Asíncrono de OCR (Proceso Autónomo)
  • Consume tareas de la cola receipt_jobs en PostgreSQL.
  • Usa FOR UPDATE SKIP LOCKED para concurrencia limpia.
  • Protegido con Circuit Breaker (opossum) y reintentos con backoff.
Semana 9 · Principio Central 04 / 13

Construcción Dirigida por Datos vs. Lógica Imperativa

Sustitución de condicionales booleanos por estructuras de datos independientes.

❌ Enfoque Imperativo (Antes)

Reglas de negocio dispersas en condicionales if / else mezclados con controladores y repositorios.

// Modificar una regla obligaba a recompilar: if (metodo !== 'EFECTIVO' && !foto) { throw new Error("Voucher obligatorio"); }
Alta complejidad ciclomática y riesgo de regresiones.
✅ Dirigido por Datos (Ahora)

Las reglas residen en matrices estructuradas. El motor de ejecución solo consulta los datos en $O(1)$.

// Consulta directa desacoplada del código: const regla = TABLA_REGLAS_PAGO[metodo]; if (regla.exigeEvidencia && !foto) ...
Búsqueda en O(1), código limpio y configurable en caliente.
Semana 9 · Máquinas de Estado Finito 05 / 13

Máquinas de Estado Finito (FSM)

Topología estricta que previene transiciones ilegales matemáticamente por diseño.

Ciclo de Vida Formal del Comprobante:
📸 1. CARGADO
→
🔍 2. PROCESANDO
→
🍽️ 3. EXTRAÍDO
→
💳 4. CONFIRMADO
Restricción Matemática (Diapo 4)

El autómata valida la matriz de adyacencia de estados. Si un estado origen no tiene como sucesor al estado destino, lanza 409 Conflict instantáneo.

Código en src/common/fsm.ts
export const RECEIPT_FSM = new StateMachine([ { from: 'CARGADO', to: ['PROCESANDO'] }, { from: 'PROCESANDO', to: ['EXTRAÍDO', 'FALLIDO'] }, { from: 'EXTRAÍDO', to: ['CONFIRMADO'] }, { from: 'CONFIRMADO', to: [] } // Inmutable ]);

Semana 10 · Contexto de Diagnóstico 09 / 13

Logs con MDC (Mapped Diagnostic Context)

Propagación transparente de metadatos en hilos asíncronos sin ensuciar la firma de los métodos.

Payload JSON Estructurado Emitido:
{ "timestamp": "2026-11-20T21:10:05.120Z", "level": "INFO", "event": "payment.create", "trace_id": "8a3c60f7-b24a-4e92", "user_id": "usr_andres", "ip_address": "192.168.1.15", "amount_cents": 3500, "method": "YAPE" }
Implementación en Node.js (Diapo 3)

En Java se utiliza org.slf4j.MDC. En TypeScript/Node.js se implementa mediante AsyncLocalStorage.

El middleware HTTP inyecta el trace_id. Cualquier llamada a logger.info() lo hereda automáticamente.
